# taxonomy — rung 1 of the ladder, Devcraft

The tracked vocabulary a Devcraft engagement's `trace/labels.md` draws its `failure_code` column from. This is Devcraft's own file, for the seat failure modes its own labels earn. The families every studio shares (today the **process-waste** family) live in the shared kit's [craftwork/trace/taxonomy.md](../../craftwork/trace/taxonomy.md), and `check.py` reads both ([studio.py](studio.py) names this file). Shapes of failure only: no engagement content, no private text, nothing a recruiter should not read.

**Rung 1 has not opened for Devcraft.** The file was created at scaffold on 2026-10-08. A seat failure mode lands here only from about thirty labelled passes of Devcraft's own, proposed with its counts and ratified by Sean with a date. Other studios' modes are not inherited.

Until then a label carries a shared process-waste code or leaves the column blank. A blank column is the normal state, and it passes.
