# Systemcraft's tools

One mastery guide per tool: how to get the very best out of it, not just how to switch it on. The lead reads a guide before using the tool on a job.

## What a good guide covers

- **What it's best at**, and where another tool beats it.
- **Setup:** what to install or sign up for, what it costs, and the one command that proves it works.
- **Getting the best out of it:** the settings, habits and tricks a master uses, with an example of the difference they make.
- **Where it goes wrong:** the common failures and how to spot each one early.
- **Safety:** what it uploads or spends, and when to ask Sean first.

Tools are scouted, not inherited. When a better tool turns up, tell Sean what it would take to get it, and write its guide once he has it. An old restriction on a tool is a question for Sean, not a rule.

## The guides

Start with the tool list, which has the picks, the prices, the privacy notes and Sean's answers. Then one guide for each kind of work:

- **Showing Sean a design:** the design pictures guide. One design per picture on a house review page, with the weaker version underneath.
- **Drawing a bigger system:** the D2 guide. It opens with the same system drawn in D2 and in Mermaid, side by side.
- **A cheap working sketch:** the Claude Code sketches guide. A skill, helpers and hooks, run with nobody at the keyboard, with a cap on spending.
- **Seeing what a run did:** the transcripts and Phoenix guide. Reading a saved run whole, and what to use when there are too many to read.
- **Deciding how a design is judged:** the promptfoo guide. The first cases read by hand, then checks worth repeating. Always run with its usage reporting switched off.
- **What a design costs to run:** the price pages and ccusage guide. Prices read fresh, the sum a design needs, and what past runs really used.
- **Checking a design for safety:** the safety checklist and sandbox guide. Five questions on one page, then the claims that matter tested on something running.
- **Keeping up with models and tools:** the changelogs and Context7 guide. What changed since a design was last touched.

Two picks are borrowed, and their guides stay where they live:

- **What a design can count on overnight:** Devcraft's guide to launchd, the Mac's own scheduler.
- **Research that changes a call:** Productcraft's guide to Codex as the second researcher.

The research behind the book list is here too.
